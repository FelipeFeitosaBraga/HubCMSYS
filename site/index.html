Prepare um PC para o CMSYS
com alguns cliques.

O Hub CMSYS automatiza a preparação de cliente novo e a troca de servidor: rede, firewall, estrutura, SQL Server 2025, restauração do banco, instalação do CMSYS e migração dos arquivos.

Antes de tudo

Primeiros passos

1

Baixe e copie

Baixe o HubCMSYS.exe nesta página e coloque no PC do cliente (área de trabalho, pen drive ou pasta de rede). É um arquivo só.

2

Abra como administrador

Dê dois cliques e clique em Sim na janela do Windows. Se aparecer "o Windows protegeu o computador", clique em Mais informações → Executar assim mesmo.

3

Siga a ordem dos botões

Clique de 1 a 7, ou use Executar tudo. Cada botão abre uma janela preta mostrando o que está acontecendo. Pode rodar de novo: nada é duplicado.

Tenha em mãos: internet no PC, o código da empresa do cliente (para baixar o backup) e, em troca de servidor, o nome do servidor antigo na rede.

Escolha o seu cenário

Dois caminhos

Cliente novo instalação do zero

PC limpo, cliente começando no CMSYS ou servidor novo sem dados para trazer.

Troca de servidor migração

O cliente já tem um servidor e vai para uma máquina nova na mesma rede.

  1. 1–7 Prepare a máquina nova como no cliente novo
  2. 8 Migrar arquivos do servidor antigo
  3. ✓ Conferir XML, notas, fotos e logo no CMSYS

O botão 8 não apaga nada no servidor antigo nem no novo.

Passo a passo

O que cada botão faz

Marque as etapas conforme for concluindo. O progresso fica salvo neste navegador.

0 de 8 etapas
1 Rede como Privada segundos

Troca as conexões de rede Públicas para Privadas, para que as estações enxerguem o servidor. Redes de domínio não são alteradas.

Confira: em Configurações → Rede, a conexão aparece como "Privada".

2 Firewall + portas segundos

Desativa o Firewall do Windows e cria as regras de entrada e saída para TS (porta 3389) e SQL (porta 1433), sem duplicar se já existirem.

3 Baixar estrutura CMSYS 10–40 min

Baixa o cmsys.zip (~1,7 GB), confere se veio inteiro, extrai e copia para C:\cmsys ou para o disco escolhido. Se a internet cair, continua de onde parou.

Sem internet boa? Coloque o cmsys.zip na mesma pasta do HubCMSYS.exe: o botão usa o arquivo local e não baixa nada.

4 Instalar SQL Server 2025 + SSMS 15–30 min

Instala o SQL Server 2025 Express (instância MSSQLSERVER, modo misto, usuário sa) e o SSMS, com as mesmas escolhas do manual. Precisa de internet.

No final, o Hub pergunta: "Quer já restaurar o banco do cliente agora?"

  • Sim → segue direto para a etapa 5.
  • Não → fica só o SQL instalado. Use o botão 5 depois.

Prova do limite de 50 GB: no SSMS, rode a consulta abaixo. Deve mostrar versão 17 e Express Edition.

SELECT SERVERPROPERTY('ProductMajorVersion') AS Versao,
       SERVERPROPERTY('Edition') AS Edicao;
5 Restaurar banco do CMSYS 5–20 min

O Hub pergunta se você já baixou o .bak do cliente.

Já baixei

  1. O Hub sugere o .bak mais recente da pasta Downloads.
  2. Confirme ou escolha outro arquivo.

Ainda não

  1. Digite o código da empresa: usuário e senha aparecem prontos, com botões Copiar.
  2. Abrir portal → faça o login.
  3. Abrir página do backup → baixe o backup.
  4. Quando o download termina, o Hub pega o arquivo sozinho.

Depois ele move o .bak para cmsys\Suporte\SQLSERVER2025 e restaura como cmsys (filial 1) ou cmsys_f2, cmsys_f3… pela filial no nome do arquivo. Também liga TCP/IP e Pipes nomeados e reinicia o serviço.

Com a extensão Auto Login Azure no navegador, o login se preenche sozinho ao digitar a empresa.

Segurança: se o banco já existir, ele não é sobrescrito.

6 Instalar CMSYS na estação 5–10 min

Instala tudo em silêncio, nesta ordem, usando os instaladores de cmsys\Suporte:

  1. ReportViewer 2010: pula se já estiver instalado.
  2. Crystal Reports Runtime 2008: pula se já estiver instalado.
  3. CMSYS Relatórios: remove todas as versões antigas e instala a nova.
  4. CMSYS Boleto: cria C:\CmsysBoleto e instala nessa pasta.
  5. Componentes do CMSYS: copia só o que falta ou está mais antigo e registra. Nunca troca arquivos do próprio Windows.
7 Windows Update varia

Procura, baixa e instala as atualizações do Windows. Fica por último porque pode pedir reinício (e o instalador do SQL recusa instalar com reinício pendente).

Se pedir reinício: reinicie e rode o botão de novo até não sobrar nada. Reiniciar derruba o acesso remoto por alguns minutos.

8 Migrar arquivos só troca de servidor

Veja a seção Migração de servidor logo abaixo.

Executar tudo

Roda de 1 a 7 em sequência e mostra um resumo no final. Entre o SQL e o restore ele faz as perguntas do banco, então fique por perto nessa hora.

Problemas comuns

"O Windows protegeu o computador" ao abrir o Hub

Acontece porque o .exe não é assinado digitalmente. Clique em Mais informações → Executar assim mesmo. Se o antivírus bloquear, libere o arquivo ou rode a partir da pasta do projeto com python hub.py.

Restore: "Erro do sistema operacional 5 (Acesso negado)"

O serviço do SQL não conseguiu ler o .bak. A versão atual do Hub já corrige isso sozinha. Numa versão antiga, rode no CMD como administrador e clique no botão 5 de novo:

icacls "C:\cmsys\Suporte\SQLSERVER2025\NOME_DO_ARQUIVO.bak" /grant "NT SERVICE\MSSQLSERVER:R"
SQL: "Invalid value 'Advanced' for setting 'MediaType'"

Era de uma versão antiga do Hub; a atual baixa a mídia correta. Plano B: copie a pasta da mídia já extraída (a que tem o setup.exe) de outro PC para C:\SQL2025 e rode o botão 4 de novo.

SQL não instala: "reinício pendente"

Reinicie o Windows e rode o botão 4 de novo. Por isso o Windows Update fica por último.

Botão 4, 5 ou 6: "Não achei a pasta cmsys\Suporte"

Rode antes o botão 3. Ele cria a estrutura em C:\cmsys (ou no disco escolhido) e os outros botões procuram em todos os discos.

Portal: o Hub não pegou o .bak baixado

O Hub vigia a pasta Downloads do usuário logado e só aceita arquivos baixados depois que a janela abriu. Se o navegador salvou em outro lugar, clique em Escolher arquivo... na janela.

Migração: "Não consegui abrir a origem"

Confira o nome do servidor, se ele está ligado e na mesma rede, e se a pasta é acessível (teste \\SERVIDOR\c$ no Explorer). Se pedir login, preencha usuário e senha na janela (ex.: SERVIDOR\Administrador).

Onde ficam os logs?

Em C:\ProgramData\CMSYS_Preparacao. O botão Abrir pasta de logs do Hub leva direto até lá. Mande esses arquivos para o suporte se precisar de ajuda.

Nenhum problema com esse termo. Tente outra palavra.

    Como funciona a atualização

    Marque as etapas conforme for concluindo. O progresso fica salvo neste navegador.

    0 de 7 etapas

    Lê a versão nova no repositório e compara arquivo por arquivo com o servidor. O painel mostra:

    • # arquivo protegido (configuração, nunca trocado)
    • a situação dos Schemas e do CMSYS Relatórios

    Confira: o topo da janela mostra a pasta cmsys, a versão instalada e a versão do repositório.

    2 Atualizar servidor e fechar o Integrador segundos

    Clique em Atualizar servidor e confirme. Se o Integrador.exe estiver aberto, o programa pede para fechar: clique em Sim. Ele é reaberto no final.

    O painel mostra qual computador e qual usuário estão com o CMSYS aberto.

    Tentar de novo

    1. Peça para fecharem o CMSYS.
    2. Clique em Tentar de novo.

    Cada arquivo baixado é conferido pela impressão digital (SHA) do GitHub antes de ir para o servidor.

    Segurança: se algo falhar no meio da cópia, o programa desfaz sozinho e o servidor volta ao estado anterior.

    5 CMSYS Relatórios só se o CMSYS era anterior à 295

    Automático, só para quem estava abaixo da 295:

    1. Acha a pasta do Relatórios do cliente: Setup CMSYS 2010 - depois de 295 ou Setup CMSYS 2010.
    2. Move o cmsysRelatoriosSetup.msi antigo para o Versões Anteriores da pasta dele.
    3. Desinstala o CMSYS Relatórios antigo e instala o novo, em silêncio.

    Depois, rode o InstalarCMSYS.exe em cada estação para trocar o Relatórios nelas também.

    6 AzureWorker 2–10 min

    O programa mostra as linhas de Empresa e Filial do CMSYS.ini, confirma a versão (ex.: 3.0.357) e já deixa ela copiada. Ao abrir o AzureWorker:

    1. Clique em Abrir e selecione o CMSYS.ini indicado (ex.: C:\cmsys\CMSYS.ini).
    2. Confira Empresa e Filial.
    3. No campo Versão Sistema, cole com Ctrl+V.
    4. Clique em Executa Procedures e espere terminar.
    5. Clique em OK e feche o AzureWorker.

    O CMSYS.ini tem que ser o da filial que está sendo atualizada. As procedures rodam no banco que ele aponta.

    7 Integrador e cliente liberado segundos

    Ao fechar o AzureWorker, o programa pergunta se as procedures rodaram sem erro.

    • Sim → reabre o Integrador e mostra CLIENTE LIBERADO.
    • Não → não reabre o Integrador e mostra onde está o backup. Resolva o erro ou use Restaurar backup.

    No fim, apague o AtualizarCMSYS.exe do servidor do cliente.

    Publicar uma versão nova

    Saiu um CMSYS.exe, uma DLL ou um Integrador novo? Leva uns 5 minutos. Assim que o push termina, todo servidor atualizado depois já recebe a versão nova.

    1. Fetch originNo GitHub Desktop, pegue o que algum colega publicou (e Pull origin, se aparecer).
    2. Copie só os arquivos novosPor cima dos antigos, na pasta certa dentro de cmsys\ (tabela ao lado).
    3. Edite o versao.txt1ª linha = versão nova do CMSYS.exe (ex.: 3.0.358).
    4. Commit to mainResumo com a versão e os arquivos: 3.0.358 - CMSYS.exe, cmsysNotaFiscal.dll.
    5. Push originPronto: já está valendo para os próximos clientes.
    6. Tag (recomendado)History → botão direito no commit → Create Tag → v3.0.358 → Push.

    Problemas comuns

    Precisa voltar a versão anterior?

    Botão Restaurar backup → escolha a data → confirme. Antes de restaurar, ele guarda o estado atual em ..._antes-de-restaurar. O CMSYS Relatórios e as procedures do banco não voltam sozinhos.

    Token do GitHub inválido ou vencido (401)

    O token foi apagado, venceu ou foi colado errado. Gere um novo no GitHub (Settings → Developer settings → Fine-grained tokens, Contents: Read-only só no UpdateCmsys) e cole quando o programa pedir.

    Repositório ou versão não encontrado (404)

    Nome do repositório errado, tag que não existe (ex.: v3.0.358 sem ter criado a tag) ou token sem acesso ao UpdateCmsys. Confira em Repository access → Only select repositories.

    GitHub recusou o acesso (403)

    Token sem a permissão Contents: Read-only, ou pendente de aprovação na organização. Ajuste a permissão ou aprove o token.

    Sem conexão com o GitHub

    O servidor está sem internet ou o firewall/proxy bloqueia. Libere api.github.com na porta 443 e teste abrindo o site no navegador do servidor.

    Arquivos em uso: não deixa atualizar

    Alguém está com o CMSYS aberto numa estação ou no próprio servidor. O painel lista computador e usuário. Peça para fecharem e clique em Tentar de novo. Derrubar conexões só com autorização.

    Um arquivo novo não foi trocado ("mantido: mesma versão")

    O arquivo do repositório tem a mesma versão do que está no cliente. O programa nunca troca por versão igual. Publique o arquivo com a versão incrementada.

    "Backup incompleto" ou "Arquivo baixado corrompido"

    Disco cheio, sem permissão ou internet instável. Nada foi alterado: libere espaço ou espere a internet estabilizar e rode de novo.

    Instalação do CMSYS Relatórios terminou com código de erro

    Abra o msi_relatorios.log no Versões Anteriores da pasta do Relatórios e procure por Return value 3. As linhas logo acima mostram a causa.

    As procedures deram erro no AzureWorker

    Responda Não na pergunta final: o Integrador continua fechado. Confira se o CMSYS.ini é da filial certa e se a Versão Sistema está correta. Se precisar, use Restaurar backup para voltar os arquivos.

    "Não achei a pasta cmsys"

    A pasta não está na raiz de um disco. Clique em Trocar... no topo da janela e escolha a pasta cmsys (a que tem a pasta Aplicativo).

    "O Windows protegeu o computador" ao abrir

    O .exe não é assinado digitalmente. Clique em Mais informações → Executar assim mesmo.

    Onde ficam os logs?

    Botão Abrir log na janela. O arquivo fica em C:\ProgramData\CMSYS_Preparacao\atualizar_cmsys_<data_hora>.log e, quando há atualização, uma cópia vai para cada pasta de backup (atualizacao.log e LEIA-ME.txt).

    Nenhum problema com esse termo. Tente outra palavra.
